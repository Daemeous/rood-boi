# Modern Menus — Phase 7a: Loot and Workshop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native Loot screen (after battles and chests) and a native Workshop inside the Items tab (assemble, gems, disassemble, repair, combine, rename), each leaving game RAM byte-identical to the original screens (parity tests), behind `ui_menus`.

**Architecture:** Loot is a direct-entry session (not Triangle): a new `#ifdef ROOD_PC` hook at the head of `vs_mainMenu_exec`'s `D_800F4EA0 & 0x200` branch (MAINMENU C48.c:363) — `pc_ui_direct_tick(selectedMenu, submenuState, &submenuReturn)` — lets a native screen speak the `vs_menuX_exec` protocol (0 stay, 1 done) for `selectedMenu == 12`, with its own lifecycle (open on the first tick with `*state == 0`; world freeze/HUD hide like the originals: `func_8008A4DC(0)`, `func_800CB654(1)`, `D_800EB9B0 = 0x200000`, undone on exit; reset/abandon paths). Workshop lives in the Items tab as a "Workshop" sub-tab (reached from the Triangle session; no direct entry). Bridges: `loot_bridge.c`, `workshop_bridge.c`; shell screens; draw files.

**Ground rules:** as earlier phases (branch `claude/musing-haslett-8e55eb`, merge main first, ROOD_PC + commit-check, three builds + decl check (now incl. the LP64 alias scanner), `run.py -j 2` one at a time, never build in the main checkout, no personal paths / emails / other-project names / game data in commits, leak scan before merge requests; don't touch other agents' files). Use main's save-room checkpoint (`pc/tests/checkpoints.py launch_at`) and `room_goto` (dev_rpc) for test fixtures.

## Facts (research brief)

**Direct entries** (`vs_mainMenu_exec` 0x200 branch, C48.c:363-384): 12 → `vs_menuB_exec` (Loot), 13 → `vs_menuC_exec` (Setup/Workshop), 8 → `vs_menu8_execRename`, 14 → MENUD, 15 → MENUF, 3 → ability unlock, 7 → container/game over. `pc_ui_menu_open` refuses non-top-level sessions; the heartbeat abandons when `currentMenu & 0x3F != 0` — the direct-entry hook needs its own lifecycle.

**Loot (MENUB 260.c):** entries `func_800CB158(_lootListHead)` (after battle: 146C.c:3539, 8423, 8554) and `func_800CB18C` (chest loot, 146C.c:5354, `unk10 < 0x40`), both `func_800CACD0(0xC, 2)`; pointers `D_800EB9C4` (list) / `D_800EB9C8` (single). `vs_battle_lootListNode` (146C.h:787, 0x228) holds `vs_battle_loot`: weapon, blade, grip, shield, armor[2], accessory, gem, misc[3], each with `difficultyFlags`. `vs_menuB_exec` (1814) / `_processLootMenu` (1491): scratch `_inventory` + backup + two 160-entry lists; `_applyAllLootLists` copies drops for the current difficulty; Square = take all (`vs_mainMenu_copyItem(cat | 0x10, &vs_main_inventory, idx, _inventory)` per entry; keys (misc id > 457) → `_setKeyFlag` → `vs_battle_setStateFlag(id + 438, 1)`); Circle = take one; when it doesn't fit, `_organizeInventory`: Organize (shared Items browser to discard), Disassemble (`_disassembleItem` 216), Consolidate misc (`_consolidateMiscItems` 433); Cross = `_discardItems` (warns about keys / untouched chest); exit: `D_800F4E98.unk2 = (result == 1)`, free, `func_8008A6FC()` when from the list. `vs_mainMenu_copyItem` is MAINMENU code (resident in this session) or port it (2D10.c:1347). Capacities display `_displayInventoryCapacities`.

**Workshop (MENUC 168.c):** reached from Items (MENU3) state 7: `returnState = currentMenu; currentMenu = 13; D_800F4EA0 |= 0x200`. Rows: Assemble (greyed at 8 weapons), Gems, Disassemble, Rename (greyed with no weapons), Repair, Combine; `_currentWorkshop = vs_battle_inWorkshop()` (146C.c:16710); outside a workshop all but Rename greyed ("notInWorkshop"); `vs_mainMenu_rebuildInventory(0..6)` on entry.
- Assemble (`_assembleMenu` 1057, `_assembleWeapon` 309): writes weapon blade/grip/gems, `assembledWeaponIndex`, gem `setItemIndex`, name = terminators, rebuild(0); `_isValidGrip` (359) `_validGripFlags[grip->category]` vs blade category; then rename hand-off (`stringBuf[0] = 0`, `stringBuf[1] = item`, `currentMenu = 8`); cancel → `_leaveAssembleMenu` → `_disassembleWeapon`.
- Gems (`_attachGemsMenu` 1541, `_attachGems` 1498): weapon/shield `gems[]` + gem `setItemIndex`; equipped → re-equip (`vs_battle_equipWeapon/Shield`).
- Disassemble (1963) `_disassembleWeapon`/`_disassembleShield` (281/344); equipped → unequip (`vs_mainMenu_unequipWeapon/Shield`, 2117) → model reload.
- Rename (2226 → MENU8 `vs_menu8_execRename` 21A0.c:820): writes `weapons[id].name` 24 bytes (`_copyNormalizedString`, padded with `vs_char_zero`; blank → blade item name); equipped → re-equip; grid UI from `rename.vsString`.
- Repair (2355): every blade, shield, non-accessory armor: `currentDp = maxDp`, `currentPp -= (maxDp - currentDp) / 100` (≥ 0); equipped re-equipped; sfx `0x7E, 0xD`.
- Combine (`_combineTopMenu` 4208): blades / shields / armor (≥ 2 items); material filter `_workshopMaterials[_currentWorkshop] >> material & 1` (table at 1055 `{0, 0xE, 0x18, 0x38, 0xC0, 0x3E, 0xFE}`, workshop id 1-6); commit (blades ~3060, shields 3681, armor 4163): parent weapon disassembled (+ unequipped), both sources `initItem`, result copied into the first slot (index kept), rebuild. Tables from `BLADE.SYD` / `SHIELD.SYD` / `ARMOR.SYD` (header `_syd` 4646 `{combinationsOffset, materialsOffset, initDataOffset}`; blades: result `comb[a.id * 96 + b.id]`, material `mat[(a.mat-3)*500 + a.cat*50 + (b.mat-3)*10 + b.cat]`, 16-byte init records; shields `comb[a.sub*17 + b.sub]`, `mat[a.mat*8 + b.mat]`; armor `comb[(a.sub-16)*65 + (b.sub-16)]`, `mat[a.mat*128 + (a.cat-2)*32 + b.mat*4 + (b.cat-2)]`); stats from `vs_main_materialModifiers[mat][24/26/28]`, DP/PP averaged, `_setClassAffinities` / `_setTypeValues` (4497-4644). Read the SYD files from the disc like `item_names.c` (`find_file`); never write them anywhere.
- Strings: `MENU12.BIN` (`vs_mainMenu_menu12Text`), MENU8 `rename.vsString`.
- Risks: per-workshop material masks; the weapon-slot byte in `gems[3]`; equipped-weapon model reloads (reuse equip_bridge's busy/hold); byte-for-byte list order.
