> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native Loot screen (after battles and chests) and a native Workshop inside the Items tab (assemble, gems, disassemble, repair, combine, rename), each leaving game RAM byte-identical to the original screens (parity tests), behind `ui_menus`.

**Architecture:** Loot is a direct-entry session (not Triangle): a new `#ifdef ROOD_PC` hook at the head of `vs_mainMenu_exec`'s `D_800F4EA0 & 0x200` branch (MAINMENU C48.c:363) — `pc_ui_direct_tick(selectedMenu, submenuState, &submenuReturn)` — lets a native screen speak the `vs_menuX_exec` protocol (0 stay, 1 done) for `selectedMenu == 12`, with its own lifecycle (open on the first tick with `*state == 0`; world freeze/HUD hide like the originals: `func_8008A4DC(0)`, `func_800CB654(1)`, `D_800EB9B0 = 0x200000`, undone on exit; reset/abandon paths). Workshop lives in the Items tab as a "Workshop" sub-tab (reached from the Triangle session; no direct entry). Bridges: `loot_bridge.c`, `workshop_bridge.c`; shell screens; draw files.

**Ground rules:** as earlier phases (branch `claude/musing-haslett-8e55eb`, merge main first, ROOD_PC + commit-check, three builds + decl check (now incl. the LP64 alias scanner), `run.py -j 2` one at a time, never build in the main checkout, no personal paths / emails / other-project names / game data in commits, leak scan before merge requests; don't touch other agents' files). Use main's save-room checkpoint (`pc/tests/checkpoints.py launch_at`) and `room_goto` (dev_rpc) for test fixtures.

## Review notes (Workshop, after task 2)

- **Gems and the re-equip (decided):** `vs_battle_equipWeapon` / `Shield` end the actor's enchantments (`func_8006B214` / `B270` / `B2D4` clear their status bits), so the native Gems re-equips exactly when MENUC does. MENUC attaches each pick at once and re-equips then (168.c:1820-1860); its Yes changes nothing more (1912-1920); every way out of the slots without Yes (Cross, Triangle, the pick list's Triangle, Cancel on the Yes / No) is `_attachGems(targetGems)`: the gems as they were, re-equipped (1855, 1873, 1928). The shell keeps the choice until Attach, so Attach after at least one pick (`PC_UI_WS_EDITED`, even if the gems end as they were) attaches and re-equips; Attach with no pick changes nothing (sound and memories only, the enchantment stays); leaving the slots any other way (Cross, Triangle, a tab or category switch, a click on a command) sends `PC_UI_REQ_WS_GEMS_LEAVE`, which re-equips an equipped target as `_attachGems(targetGems)` does. A shell closed from the game's side (the bridge's abandon) sends nothing. `ui_workshop_smoke` compares Ashley's battle record after every operation, including gems on the equipped weapon and an enchanted equipped weapon through Attach without a change (kept on both sides) and a back-out (ended on both sides).
- **Cursor memories on back-out paths (documented, not modelled):** MAINMENU's lists store their cursor memory when backed out of too (58EC.c:1012, 1046), so the original reopens a list where it was left after Cross / Triangle; the native flows keep their own cursors and write MENUC's memories (ids 53..61) only for the choices they carry out (`workshop_bridge.c` header). The parity test compares memories after completed operations only.
- **Name field:** the pad grid overwrites the character at the cursor and moves on, as MENU8 does (21A0.c:637-644); keyboard typing inserts at the cursor (a text-field convenience with no counterpart in the original). Typing arms only once no key is held after the field opens; Enter / Escape act on a press, not on its auto-repeat. Requests carry the name.
- **Refused requests:** the shell goes back to the step that sent the request (its choices and the name kept) and shows the refusal line.
- **Loot merge (user decision):** the Loot screen's Organize inventory merges misc stacks as the Items menu (MENU3) does, the sum kept; MENUB's own copy loses the stack moved. `ui_loot_smoke` asserts both sides of this one difference.
